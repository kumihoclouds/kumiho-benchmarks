# Kumiho Memory — 예상 반론과 답변 (마케팅/발표 Q&A 대비)

> 2026-07-09 기준. 발표·포스팅·커뮤니티 대응용.

## 지표/벤치마크

**Q. "다른 시스템은 90%대인데 0.531은 낮은 거 아닌가?"**
그 90%대는 LLM-as-judge 정확도다. LoCoMo 공식 지표는 토큰 F1이고, judge는 F1보다 1.5–2× 높게
읽히는 다른 지표라 직접 비교가 안 된다. F1 기준 공개 수치로는 Kumiho 0.531(고정 모델
gpt-4o-2024-08-06, 오늘 재현되는 헤드라인)이 공개된 경쟁치 (Mem0 ~0.40, OpenAI ~0.343 등)를
상회한다. 우리도 judge를 돌릴 수 있지만, 부풀릴 수 없는 지표로 공개한다.

**Q. "재현 가능한가?"**
방법과 고정 모델 기준으로 가능하다. SDK와 벤치마크 하네스가 오픈이고, README의 커맨드로
로컬 CE에서 재현된다. 재현되는 것은 리콜/기억 레이어와 그 위에 얹은 고정 모델 기준 수치(0.531)다 —
end-to-end F1은 앱이 고르는 답변 모델에 따라 움직인다. 과거 2월(0.565)과 v0.9.0(0.564) 피크는
그날의 unpinned gpt-4o로 측정된 드리프트-시대 기록이라 현재 모델에서 재현되지 않고 날짜 간
직접 비교도 안 된다 — 동일한 리콜 컨텍스트를 이후 스냅샷에 다시 물으면 모든 스냅샷에서 −0.056이
나왔다(frozen-context 실험). 바로 그래서 지금은 답변 모델을 gpt-4o-2024-08-06으로 고정하고
응답마다 system_fingerprint를 로깅한다. 우리가 주장하는 재현성은 드리프트하는 모델 위의
날짜-교차 절대점수가 아니라 방법 + 고정 모델 수치(0.531)의 재현성이다.

**Q. "+0.054는 왜 4카테고리 기준인가?"**
adversarial(함정 문항)은 대부분의 baseline이 별도 보고하지 않는 카테고리라, 표준 4카테고리
기준으로 밝힌다. adversarial 포함 5카테고리 overall 델타는 +0.046 — 이것도 함께 공개한다.
(참고: adversarial 자체도 +0.021 상승했다. 숨기는 카테고리가 없다.)

**Q. "단일 대화(conv-26) 측정은 신뢰할 수 있나?"**
페어 설계라서 가능하다. 같은 코퍼스·같은 질문에서 변수 하나(fact 레그)만 바꾼 A/B고,
문항별 23승 172무 4패(부호검정 p≈0.0002)다. 단일-런 절대점수는 ±0.05 흔들리지만
페어 델타는 그 노이즈와 무관하다. 절대점수 주장은 full-suite(n=1,986)에서만 한다.

## 아키텍처

**Q. "Mem0-Graph, Zep도 그래프인데 뭐가 다른가?"**
셋 다 "그래프"라는 단어를 쓰지만 구조가 다르다. Kumiho의 차별점:
1. **write-time 타입 분해** — 대화 저장 순간 fact/decision/event/entity가 각각 임베딩을 가진
   1급 버저닝 노드가 됨 (사후 배치 아님, 추가 LLM 콜 0).
2. **결정론적 엣지** — 토큰 경계 매칭·중첩 임계로만 연결. 환각 엣지가 없고 재현 가능.
3. **구조-인지 리콜** — 엔티티-브리지 조인(그래프 JOIN), fact 직접 검색, 추가-비대체 조립.
   그래프를 "저장만" 하는 게 아니라 리콜 알고리즘이 구조를 소비한다.
4. **전 기억 버저닝 + SUPERSEDES** — 신념 갱신이 구조다 (LoCoMo-Plus 93.3%의 기반).

**Q. "온톨로지를 켜면 느려지거나 비싸지지 않나?"**
분해는 결정론적(LLM 0콜)이라 인제스트 비용 증가는 그래프 쓰기뿐이다. 리콜은 fact 레그 검색
1회(+수십 ms)와 엣지 순회가 추가된다. 품질은 페어 측정으로 +0.054, 회귀는 additive 설계상
구조적으로 차단된다 (실측 손실 문항 199개 중 4개).

**Q. "온톨로지가 잘못 뽑으면?"**
세 겹의 방어: ① 요약 스키마가 온톨로지와 무관하게 동일 (기본 요약 품질 무영향)
② 엣지는 임계 미달이면 생성 안 됨 ③ 리콜에서 구조 증거는 기반 컨텍스트를 대체하지 못하고
위에만 얹힘 — 최악의 경우에도 기존만큼은 나온다.

## 오픈소스/사업

**Q. "핵심이 오픈인데 사업이 되나? / 서버는 왜 비공개인가?"**
오픈코어다. 기억이 어떻게 생각해야 하는지(인지 레이어)는 열어서 검증받고 —
그래서 벤치 수치가 "믿어달라"가 아니라 "돌려봐라"가 된다 — 그것을 빠르고 안전하게
멀티테넌트로 돌리는 엔진(Rust 서버)이 제품이다. GitLab/Neo4j와 같은 구조.
로컬 개발은 무료 CE로 가능하므로 재현성도 유지된다.

**Q. "SDK만 보고 경쟁사가 베끼면?"**
리콜 정책은 볼 수 있지만, 하이브리드 융합·인덱스 위생·한국어 형태소 인덱싱·멀티테넌시가
서버에 있다. 그리고 이 설계의 진짜 해자는 코드가 아니라 **측정 문화**다 — 모든 지표가
페어 A/B와 임계 실측으로 조정돼 있고, 그 측정 인프라와 노하우는 이식이 안 된다.
